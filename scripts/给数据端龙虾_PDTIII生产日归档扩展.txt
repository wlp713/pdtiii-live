# 给【Windows 数据端设备】龙虾的自动执行指令 —— 生产日边界归档扩展（只加不改，不破稳定底座）

你是生产看板【数据端设备】上的 AI 助手。这台机器 **24 小时在工厂开机**，正在每 60 秒跑 `sync_db.py`
从生产数据库取数写入 Firebase（这是稳定的、不许动的底座）。
现在需要你在它上面**新增一个"生产日边界归档"能力**，让白班/夜班数据在源里还活着时就被存档，
不依赖任何人类电脑是否开机、也不依赖 GitHub cron。

====================================================================
## 一、目标（一句话）
新增一个**数据驱动、每 5 分钟触发一次**的归档任务：当一天的**白班(含加班段)**或**夜班**数据源里已经完整，
就把该生产日的归档 JSON 写进 `history/shifts/`，并 commit+push 到看板仓库。**只新增，不改动现有取数底座。**

====================================================================
## 二、三条【绝对红线】（宁可不动，不可破坏）
1. **绝不能动 `sync_db.py` 的取数主逻辑**——它含 Frame No.1~5 白名单（41 条线）、段边界桶降采样、60s 省流量，都是稳定底座。**只加新文件、加新 cron 行；不许改 sync_db.py / 不许删它的任何备份 / 不许整份覆盖它。**
2. **hourly 段边界桶 (HOURLY_BOUNDARY_BUCKETS, 29 个) 不变**——白班末桶 `2020`、夜班末桶 `750` 是归档判定的关键，绝不能动。
3. 已有取数 cron（每 60s sync_db）**一行都不许改**。只能**追加**新的归档行。

====================================================================
## 三、要新增的东西（一共 3 样）

### A. 归档脚本 —— 拷贝同仓库的 `scripts/archive_daily.py` 和 `scripts/history_analytics.py`
这两文件在本仓库 `pdtiii-live/scripts/` 下（你所在机器若没有，找人类要；或从 GitHub `wlp713/pdtiii-live` 拉）。
- 这俩是**纯 Python 标准库**（urllib/json/argparse/datetime），**无需 pip 装任何包**，你那台有 python3 就能跑。
- 核心入口：`archive_daily.py --shift auto`
  —— 只看数据完整性：白班源桶到 `2020`（20:20）完整 → 归档 `{D}-day.json`；夜班源 <08:00 晨桶到 `750` → 归档 `{D-1}-night.json`。
  —— **它不依赖墙钟**，只看源数据完整度。数据不完整就跳过，不会覆盖已有有效归档。

### B. 归档 wrapper —— 同样拷 `scripts/archive_cron_wrapper.sh`（改它内部路径为本机路径）
思路：跑 `archive_daily.py --shift auto` → 若 `history/shifts/` 有新归档产生 → `git commit + push` 到仓库。
**注意**：本机的 git remote 若没有 push 凭据（token），就**只生成文件 + 本地 commit，不 push**；
把 push 留给看板电脑/GitHub 兜底。别因为 push 报错就中断整个归档。

### C. 一条新的 cron 行 —— 每 5 分钟触发一次归档检测
```
*/5 * * * * cd <本机pdtiii-live路径> && /usr/bin/python3 scripts/archive_daily.py --shift auto >> logs/archive_cron.log 2>&1
```
（可选：若 git push 可用，改成调 wrapper，让它 commit+push。）
不用 20:31/08:00 那种固定墙钟 —— 每 5 分钟探一次，数据一完整就归档，最稳。
